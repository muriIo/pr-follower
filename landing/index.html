01 · The noise

A review request is an email.

A team’s worth of them is a wall.

CODEOWNERS adds you to every pull request that touches a path you, or your team, own. GitHub tells you by email: one thread per PR, another message for every push and comment.

Nothing there says which threads need you, which a teammate already approved, or which are drafts with red CI. Everything looks equally urgent. Dependabot’s bumps sit for weeks.

02 · Ownership

It reads your CODEOWNERS.

So the answer is exact, not a guess.

# .github/CODEOWNERS

*.md @acme/docs

/src/app/ @murilo @acme/frontend

/src/api/ @acme/backend

/infra/ @acme/platform

#142 · 14 files changed

src/api/seats.handler.gobackend
src/app/…/seat-card.component.tsyou
infra/ci/pulse.ymlplatform
docs/seats.mddocs
+ 10 more, none of them yours

One file’s diff, not fourteen.

Matching follows GitHub’s pattern rules. The drawer shows only the files the rule gave you. PRs you own nothing in stay out of your queue.

Honest when it can’t tell.

CODEOWNERS is re-read when a push changes it. No file means “no CODEOWNERS”, said out loud. Unknown files are “not evaluated”, never your turn.

Owning a file says the PR is yours. It doesn’t say whether the next move is.

07 · How it’s built

Your GitHub App. Your database. Your code stays put.
